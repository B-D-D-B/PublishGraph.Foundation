# SDA standalone HTML implementation plan

Create a portable folder containing the captured sda.studio website as real HTML, CSS and JavaScript. Preserve its page content, palette, layout, navigation tabs, dropdowns and captured responsive behavior. This is a static replica of the offline capture, including its known unavailable content, rather than a recreation of the current live service.

This revision proposes future execution only. The planning gate is independent D1–D8 readiness under SP-01/SP-02 and the [worker and reviewer cycle](../../../../BDDB.AITooling/guidance/worker-review-cycle.md). Readiness does not establish R1–R8 software acceptance. The [Working record](../Working/SDA-Standalone-HTML-Planning-2026-11-16.md) owns configuration, snapshots, findings and lifecycle history.

Do not change Foundation application files, project/build configuration, existing work, the sibling repository, its sources or its screenshots. Do not run a C# build, deploy, commit or push. The implementation worker owns only the new destination; the coordinator owns the existing Working record. Any destination collision blocks creation until ownership is resolved; do not overwrite or delete it.

Choose a folder with multiple HTML pages and local assets, rather than one enormous HTML file. This retains document URLs, navigation, original CSS cascade and browser back/forward behavior with less reconstruction. The deliverable runs directly in a browser and on a generic static server without CMS, PHP, .NET, build step, database, service worker or network dependency. Node and browser automation are optional development/verification tools, not runtime requirements.

The set covers home; About and four descendants; Art and six descendants; Artists and two descendants; Businesses; Collectors and four descendants; Contact; SDA Frame; Membership and seven descendants; NFT Proposal; Pulses and seven descendants; and Technology. A modern responsive redesign is outside this fidelity task.

## Implementation sequence

1. **Preflight and freeze inputs.** After the user requests execution and this exact plan has independent READY, register one implementation function, `SDA-STATIC-IMPL-01`, in the existing Working record. Assign a Sol 6.1 medium worker and a distinct Astra 6 medium reviewer; use Normal track for this bounded recovery and revalidate against the shared cycle. Record explicit launch guarantees separately from available host telemetry. Confirm owned destination absence, unchanged unrelated Git status, access to all source HTML/screenshots, the 42/84 manifest counts, and tool availability. Hash the selected HTML, transitive assets and reference PNGs before copying; preserve this input manifest and verify it again at freeze. Missing source/access blocks the affected work.
2. **Copy the captured site with its asset closure.** Preserve page DOM, inline styles, original CSS ordering, local jQuery and theme menu/scroll behavior first. Copy only the 42 HTML pages and transitive resources they use, including CSS `url()`/imports, font files, image/srcset, SVG references and local script dependencies. Detect MIME mismatches: an HTML error response is not a usable font/image/script. Preserve third-party notices with reused resources. Start with mirror reuse; reconstruct only local URL handling, unavailable external surfaces and scripts that genuinely require a backend. Do not flatten all pages into screenshots or introduce an application framework.
3. **Make URLs portable.** Rewrite every internal page link, form endpoint, root-relative asset reference and `sda.studio` absolute URL according to the mapping, using relative URLs from each containing document or stylesheet. Resolve captured sibling-host assets to copied local files. Preserve exact case and percent encoding; validate on a case-sensitive path map. Keep fragments and meaningful query parameters. Strip CMS cache-buster queries only after resolving the exact captured file; resolve HTTrack query-derived filenames explicitly and fail on ambiguous/colliding mappings. Directory/extensionless historical links must map to the existing `.html` target rather than relying on server rewrites. External social/mail/telephone links stay explicit outbound links and are never automatically fetched.
4. **Apply the bounded interaction dispositions below.** Keep real navigation anchors and their selected/ancestor styles. The inspected Animenu script toggles `.animenu__toggle--active` and `.animenu__nav--open`; the theme script handles scroll-to-top and anchor scrolling. Reuse these locally where possible. Preserve their stylesheet breakpoints and actual dropdown behavior. The top navigation's tab-like appearance represents page links; inspection found no `nav-tabs` or `tab-pane` implementation in the canonical HTML. Inventory all executable/inline handlers before removing CMS code; any actual content tabs discovered must retain their real panel switching and active styles, with explicit tests.
5. **Verify and correct inside this boundary.** Build only the small checking/capture helpers described below, run the acceptance matrix, inspect mismatches and correct supported local path/CSS/script defects. Recheck affected pages and shared-shell regressions. Keep failures visible; do not widen thresholds or replace reference images. Freeze output hashes, input hashes and actual results for one independent R1–R8 review of the complete result. Address ordinary findings within this same scope under the shared corrective-continuation rules; changed scope, oracle or risk boundary requires affected D1–D8 READY first.

## Checks and execution commands

Use PowerShell and installed Node for small helpers; verify `node --version`, `npm --version` and an available Chromium/Edge executable before implementation testing. Browser capture requires a locally available Playwright package and PNG comparison library, with exact versions recorded in a development lockfile. Reuse a suitable installed package, or install development dependencies only inside the owned destination. If unavailable, block visual acceptance rather than substitute a C# build or claim success. The original tablet environment records Playwright 1.62.1 and Edge 152.0.4191.66; record actual test environment and investigate rendering differences instead of silently rebasing.

The worker will create `tools/check.cjs`, `tools/serve.cjs` and `tools/verify.cjs` inside the destination. These are proposed files, not existing commands. `serve` must bind loopback only, accept a mount prefix, serve correct MIME types, reject traversal and perform ordinary static-file lookup without page rewrites. `verify` starts/stops its own loopback server, refuses an existing evidence run directory and returns nonzero on any required assertion failure. From the destination, the final supported commands are:

```powershell
node tools/check.cjs
node tools/serve.cjs --port 4173
node tools/verify.cjs --browser-channel msedge --run baseline
```

`check` validates the 42 mappings; transitive paths and exact case; CSS/JS/image/font MIME signatures; local fragment targets; no unintended live dependencies/backend actions; and input/source hash agreement. `verify` writes the following assertions and supporting artifacts to a new `evidence/<run>/` directory. The server command is for manual inspection and can be stopped with Ctrl+C; automated verification manages its own server lifecycle.

| Obligation | Discriminating acceptance |
| --- | --- |

## Recovery and stop conditions

Apply SP-01 safe-mutation safeguards to owned writes: one writer, retained preimage, path/hash revalidation before a context patch, immediate expected-postimage and untouched-file verification. Do not edit frozen evidence or source. For a failed helper invocation, inspect the raw error and partial effects; a path/argument spelling correction or new unused evidence-run name is allowed only inside the owned destination with unchanged product/oracle semantics, before dependent checks proceed. Preserve the failed attempt, verify changed bytes and untouched guards, then rerun only the affected check. Do not blindly replay a failed write or overwrite an existing evidence run.

Stop dependent work on unsafe/unknown state, source/hash drift, competing writers, missing required assets/tools, ambiguous URL collisions, an unsupported consequential behavior or a correction that fails without new causal evidence/progress. Preserve snapshots and failures in the existing Working record and follow the shared operational-recovery and stop/resume rules. Unrelated authorized work need not stop. No more governance artifacts, intermediate independent gates or broad tooling project are needed.
