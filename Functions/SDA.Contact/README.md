# SDA contact function

Local implementation of the [reviewed contract](../../Documentation/Projects/Plans/SDA-Contact-Azure-Function-Plan.md). Host v4, JavaScript programming model v4, Node 24, Flex 512 MB, no always-ready instances. **Production sending is unavailable:** the owner has not selected Graph or Resend or a verified sender. There is no production mock switch or mail adapter. `MAIL_ENABLED` defaults false; even setting it true cannot send until the selected adapter is implemented and independently reviewed.

Install with Node 24: `npm ci`; run `npm test`, `npm run test:storage` against loopback Azurite Table service, and `npm run test:browser`. The pinned development Node package permits isolated Windows execution through `node_modules/node/bin/node.exe`. Browser tests reuse the static site's pinned Playwright. Local mocks inject dependencies only through tests. They send no mail and contact no production challenge/provider service. Local settings and tool/runtime data are ignored; the example contains empty configuration only.

The endpoint accepts only POST JSON at `/api/contact`, plus restricted OPTIONS, with a 16 KiB stream cap, validation, server-side Turnstile metadata verification and global 50 UTC send-attempt reservations. Table SDK retries are disabled; conflict retries are bounded. Timeout/uncertain attempts are never refunded or resent. The handler sends only to the constant contact@sda.studio, uses a structured Reply-To and plain text. It logs request ID/status/code/duration only; dependency auto-collection is disabled. Never enable body/payload/secret logging.

The public page's `data-enabled="false"`, blank `data-endpoint` and blank `data-sitekey` intentionally disable online submission. Configure only a selected HTTPS Function endpoint and public Turnstile site key after staged verification. No function key or provider secret belongs in the browser. The privacy notice must name the selected provider and reflect confirmed retention before activation. Do not publish the server recipient or an email fallback in runtime HTML/JavaScript. Disabled submission shows a generic unavailable status.

Deployment remains blocked on owner-selected tenant/subscription, new resource group and unique names, region/quota, production origin, mail provider/sender, Turnstile account/site key/secret/hostname, operator and budget. Do not reuse Frame resources. Check CLI >=2.60, Core Tools v4 and Node24, `az functionapp list-flexconsumption-locations`, resource providers and quota. Build with `az bicep build --file infra/main.bicep`. After the target is approved, run group what-if against resolved nonsecret parameters; stop for name collision or effects outside the new resources. No infrastructure has been provisioned by these files. Choose a small explicit budget/alerts at 50/80/100%; the log ingestion cap is not a spend stop.

Deploy the reviewed package disabled using supported Flex tooling only after approval of that exact target/what-if. Configure secrets separately without command output. Inspect runtime, HTTPS/CORS/origin denial, managed identity permissions, zero always-ready, secret absence and telemetry redaction in the isolated stage. The template deliberately contains no provider credentials/sender or Turnstile secret. Host identity has scoped storage data roles on its new account only. Mail permissions depend on the selected provider and are absent.

Actual outgoing test mail needs the later explicit controlled-test authorization. Provider HTTP acceptance is separate from inbox arrival; require the owner's confirmation at contact@sda.studio, From/Reply-To/body/reply behavior and spam-folder check before production activation. Never claim inbox delivery from a 202. Graph selection requires scoped Exchange Application Mail.Send, usable sender and proof unrelated mailboxes are denied; remove additive broad grants. Resend selection requires verified sender domain, sending-only key, current account quotas and disabled tracking/overages where available. Implement only the chosen branch.

Rollback: disable public submission/show a generic unavailable status; set `MAIL_ENABLED=false`; stop only the new Function if needed. Restore protected preimages or reviewed package, retaining aggregate counters/evidence. Rotate a compromised provider secret separately. Accepted mail cannot be recalled and uncertain outcomes remain uncertain.
