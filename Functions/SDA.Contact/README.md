Host v4, JavaScript programming model v4, Node 24, Flex 512 MB, no always-ready instances. **Production activation remains blocked.** The owner selected Titan SMTP and sender contact@bddb.io. Install with Node 24: `npm ci`; run `npm test`, `npm run test:storage` against loopback Azurite Table service, and `npm run test:browser`, and `npm run test:smtp` (local TLS SMTP fixtures; OpenSSL CLI required to generate temporary synthetic certificates). The pinned development Node package permits isolated Windows execution through `node_modules/node/bin/node.exe`. Browser tests reuse the static site's pinned Playwright. Local mocks inject dependencies only through tests. They send no mail and contact no production challenge/provider service. Local settings and tool/runtime data are ignored; the example contains empty configuration only.

The endpoint accepts only POST JSON at `/api/contact`, plus restricted OPTIONS, with a 16 KiB stream cap, validation, server-side Turnstile metadata verification and global 50 UTC send-attempt reservations. Table SDK retries are disabled; conflict retries are bounded. Timeout/uncertain attempts are never refunded or resent. The handler sends only to the constant contact@sda.studio, uses a structured Reply-To and plain text. It logs request ID/status/code/duration only; dependency auto-collection is disabled. Never enable body/payload/secret logging.

## Titan server settings

Server-only `MAIL_FROM` and `SMTP_USER` must both equal contact@bddb.io; `SMTP_PASSWORD` is the mailbox/application password. Missing/disabled/mismatched settings expose no send dependency and return503 before challenge/reservation. Examples keep credentials empty and `MAIL_ENABLED=false`. The host is fixed smtp.titan.email:465 with implicit TLS, certificate/hostname verification and TLS1.2 minimum; no arbitrary SMTP URL/host or TLS bypass setting exists. EU-region accounts need owner confirmation and affected review before changing that fixed host. No credential belongs in static files, Git, command output or logs.

Each send owns one nonpooled connection and its socket from DNS/connect creation. Abort destroys it, and late continuations cannot start SMTP. Only final DATA250 for the fixed recipient yields202; explicit SMTP refusal/untrusted certificate yields503, and uncertain disconnect/timeout/abort yields504. A consumed reservation is never refunded. No retry, queue, alternate credential or resend occurs. Rotation: disable sending, rotate the secret in approved Function settings through the infrastructure workflow, then stage/recheck before any later activation. No deployment, real SMTP connection, outgoing message or credential configuration was performed by these local tests.
